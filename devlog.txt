# NOTE: change in registry system
At some point I realized that the username as a key wasn't a good idea since if someone wants to change there information,
the key would have to be changed in order to keep consistency. However, in my design I was going to use the keys to connect,
between classes. For example the members list in the teams class will store the keys of the members rather than the objects.
This makes it easier to save data as well as I wouldn't want to store objects in files since I would want it to be readable.

To overcome this I have created an ID system where it generates a random number from 0 to 1000 and use that for,
the key. Now when information is changed it doesn't have to change the key. This is the id generator:

def uniqueIDGenerator(registry=None, prefix=None):

    randomNum = random.randint(0, 1000)

    if not f"{prefix}-{randomNum}" in registry: return f"{prefix}-{randomNum}"

    uniqueIDGenerator(registry=registry, prefix=prefix)

The arguments are registry and prefix. The registry argument is where you pass through the registry.
This is so this function can check if the key already exists after it generates. The prefix is something I,
want to add to the key. For example for the members I will call this function like this:

uniqueIDGenerator(registry=Members.Members.registry, prefix="USER")

To clarify I have decided to create a new module called Common as for every class it will just be the same function,
copied and pasted, and it would make sense to create one function that supports all classes.

The if statement checks is the new ID generated is in the registry. If it's not then it will return the new id as we,
want it to be unique. If it is then it will call itself again to generate a new id. This is called recursion which allows
functions that repeat code to call itself rather than making a loop.

My current ID system does have some problems. For example if there are a lot of members then there is a high change that,
when creating a new member it will take a bit longer to find an available ID since it would have to loop multiple times.
It may take a too long to find an available ID which is problematic. If there are no ids left it will infinitely loop,
over and over again. What I am thinking of doing for the future is to add a more complex ID generating system involving,
letters and numbers increasing the variety and reducing chances of long loops. Considering the scope of this project,
